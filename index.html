Our Domain

Research Foundation

ANZEN: Unified AI-IoT Platform for Road Safety

ANZEN integrates four complementary AI systems into a single vehicle-mounted edge computing platform. Rather than relying on manual reporting or reactive detection, ANZEN operates continuously to detect hazards, assess accidents, predict risks, and forecast driver behavior—all in real-time.

Autonomous Detection

Automatically identifies road hazards without driver input

Live Community Mapping

Updates shared hazard maps with geofenced validation

Edge AI Processing

Real-time processing on Raspberry Pi (no cloud latency)

Predictive Intelligence

Forecasts accidents 30-60 seconds before they happen

The Problem: Road accidents cause 1.35M deaths globally per year. Sri Lanka records over 2,500 fatal accidents annually. Current systems (Waze, Google Maps) require manual reporting, which is dangerous while driving.

1. AI-Powered Road Hazard Detection & Real-Time Mapping

Literature Review

Tools like Waze and Google Maps rely on voluntary manual submissions—dangerous while driving. Prior research focused on static defects (potholes) but neglected temporary hazards like construction zones and mobile police checkpoints.

Research Gap

Lack of a unified, automatically operating system that combines detection, community validation, and lifecycle management (expiry logic) for transient hazards.

Objectives

  • Detect potholes, construction zones, and traffic police automatically
  • Remove manual reporting burden from drivers
  • Maintain up-to-date map using class-specific Time-to-Live (TTL) values
  • Validate hazards through 1 km geofenced community consensus

Technologies

Hardware: Raspberry Pi 4 (8GB), Pi Camera v2, NEO-M6 GPS
AI Model: YOLOv8 Nano trained on Sri Lankan datasets
Backend: Python FastAPI, MongoDB with TTL indexing
Frontend: React Native mobile app with geofenced validation

2. AI-Based Accident Detection & Severity Classification

Literature Review

Current solutions like OnStar provide location but lack severity information or passenger counts. Previous hybrid systems often excluded occupancy awareness.

Research Gap

No existing comprehensive alert system provides fusion of crash intensity (G-force) and real-time passenger counts for emergency responders.

Objectives

  • Detect vehicular crashes automatically in real-time
  • Classify severity: Low, Medium, High (based on G-force data)
  • Count passengers using computer vision
  • Provide emergency services with critical occupancy and severity data

Technologies

Hardware: MPU6050 Accelerometer/Gyroscope, Raspberry Pi, Camera, GPS
Severity Classifier: Random Forest (G-force based)
Occupancy Detection: YOLOv5 Nano (passenger counting)
Backend: Python (Scikit-learn, PyTorch), FastAPI, MongoDB

3. Multi-Modal Vehicle Safety System for Risk Prediction

Literature Review

Most ITS address only discrete tasks (e.g., signs OR blind spots). Many solutions fail to account for live vehicle speed when issuing alerts, leading to false alarms and driver distraction.

Research Gap

Lack of an integrated platform that combines geo-fenced bend warnings, radar-based blind spot monitoring, and speed-adaptive traffic sign alerts.

Objectives

  • Reduce human error in limited visibility zones (blind bends, hairpin curves)
  • Provide blind spot detection using microwave radar
  • Recognize traffic signs in real-time
  • Issue context-specific, speed-adaptive notifications

Technologies

Hardware: Raspberry Pi 4, RCWL-0516 Microwave Radar, Pi Camera, ELM327 OBD-II
Vision: YOLOv8n (ONNX format) for traffic sign detection
Backend: Python/Flask with OBD-II speed gating (alerts only if speed > 40 km/h)
Frontend: React Native with voice alerts

4. AI-Based Predictive Driver Behavior Analysis

Literature Review

Existing systems are reactive, detecting fatigue or stress only after manifestation. Single-modality approaches struggle with accuracy and environmental noise.

Research Gap

Absence of temporal multimodal predictive modeling with sufficient forecast horizons (30-60 seconds) to allow meaningful proactive intervention.

Objectives

  • Forecast driver emotional state transitions (Stress, Fatigue, Aggression)
  • Provide 30-60 second advance warning before emotional impairment affects driving
  • Reduce accidents caused by emotional impairment (increases risk by 300%)
  • Develop Emotional Transition Predictor (ETP) for long-horizon forecasts

Technologies

Hardware: Raspberry Pi 4B, Intel Neural Compute Stick 2, Sony IMX219 NIR Camera, OBD-II
Spatial Features: MobileNetV3 for emotion recognition
Temporal Modeling: BiLSTM with multi-head attention for sequence prediction
Classification: Random Forest & SVM for driving patterns + ETP for transitions
